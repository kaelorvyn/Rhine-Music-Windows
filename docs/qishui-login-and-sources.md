# 汽水登录与取源

汽水登录页同时显示二维码与中国大陆手机号／短信验证码表单，不使用标签切换或独立页面。未登录时打开面板自动获取二维码，使用抖音 App 扫码并确认；短信只在用户点击“获取验证码”后发送。宽窗口并排，窄窗口上下排列，其他平台登录组件不变。

短信发送与登录复用本地认证服务和原有 DPAPI 会话存储。Windows 客户端使用独立安全验证窗口，接收官方组件的完成回调，没有手动“我已完成”按钮。窗口通过原生私有管道回传所需会话，不向网页提供任意 Cookie、签名或解密接口。验证窗口完成不等于登录成功，登录仍需官方接口返回有效凭据并读取账号资料。

短信与扫码的 Passport 请求在本轮同一个原生 WebView2 安全环境中执行，由官方 Glue/bdms 对浏览器 XHR 请求签名，附带实际浏览器环境信息，Cookie 与令牌由浏览器连续维护。不再在桌面正式链路中取得令牌后交给 Node 重新签名发送。Node 只准备固定账号操作、接收绑定本轮操作 ID 的响应、校验账号并保存 DPAPI 会话。保留的离线签名代码用于协议回归，不是桌面请求的降级旁路。

本机匿名客户端标识在第一次初始化登录时创建并保存到 `qishui-client.json`，后续重用，不在限频后轮换设备。仅有 region 接口响应或随机令牌不算安全初始化。取曲的 `X-Helios`／`X-Medusa` 不复用于 Passport 登录。

错误码 7 不能单独证明是用户点得过多，也可能是官方安全校验拒绝。界面显示错误码并遵守冷却时间；HTTP 429 的重试等待传递到按钮倒计时，不自动重发短信。冷却结束后，手动重试同一手机号仍保留本轮会话。

结构化挑战使用对应的官方 SDK，不把脚本或 JSON 当网页打开。2046 账号二次验证保留官方决策与业务参数：必要时请求 `pack_verify_ways_data` 展开决策，再在 React 17、官方 Glue/bdms 环境中加载并调用 `ucWebSecondVerify`。只有组件返回 `status === true` 才继续；普通成功文字、无关消息和关闭窗口均不算成功。缺少有效决策或组件时停止并显示阶段错误，不能伪造验证入口。真实账号授权和风控通过仍需账号持有者实际验收。

二次验证在本轮浏览器环境内完成并按原操作续接一次：发送短信继续发送；短信登录保留原手机号与验证码继续登录，不额外发短信；扫码检查合入该次官方业务参数并继续检查。再次要求验证时停止自动重试。用户取消或退出页面时终止待办；刷新／过期二维码不清除已发送的短信状态，后台扫码检查不抢占文本输入。

二维码只展示生成的 PNG，不把官方返回的索引地址直接用于跳转；取出其中的令牌，生成固定官方 `bff-pc.qishui.com/light/invoke/scan_login` 地址。真实响应的索引地址可能来自 `bff-pc.qishui.com`，不能臆定其主机必须是 `api.qishui.com`。

验证组件的指定跨域请求通过 `rhine-qishui-http` 原生协议和现有私有管道转发，包装层位于 bdms 内层，保留已签名的最终 URL。仅允许已列举的官方安全服务和路径、GET/POST、64 KiB 请求与 2 MiB 响应；校验窗口身份、来源和单次会话 nonce，拒绝重定向、取消后的请求及任意账号 Cookie/Authorization 转发。请求正文与请求头不写入 URL，不增加公共 HTTP 代理。官方汽水域的验证 Cookie 在同一登录会话内保留，其他域的 Cookie 不能合入账号请求。

验证响应会检查根层以及 `data`、`captcha` 等有限嵌套中的官方地址；不能因为 `captcha` 等于空对象、`"{}"`、`"0"` 等占位值，就把所有登录错误归类为缺少验证地址。普通错误优先显示数值错误码与经过脱敏的官方说明；错误码 20028 的附加验证单独处理。普通错误和没有可用入口的附加验证不清除本轮短信挑战，不自动重新发送。

`qishui-login-diagnostic.json` 仅保留最近一次失败的阶段、HTTP状态、数值错误码、已知字段名及验证入口是否可信，不保存手机号、验证码、Cookie、令牌、响应正文或完整验证URL。该诊断用于区分实际服务响应与本地解析失败，不能代替真实账号验收。

## 音频链路

汽水歌单、歌曲和搜索封面统一使用已有本地封面代理。已确认的 `douyinpic.com` 图片虽然返回 HTTP 200，但不提供浏览器 CORS 响应头，不能直接供共享图片加载器或 WebGL 纹理读取。代理只接受对应 CDN 域，保留缓存、大小与重定向限制，不携带账号 Cookie 或授权头；不通过关闭浏览器跨域保护处理。

1. 本地官方接口只接受可确认的免费完整音频；需要签名的官方请求由随包纯 JavaScript 签名模块处理。
2. 官方未返回可用完整音频时，请求用户导入的共享音源 DLL。
3. DLL 未命中时，继续现有备用音源与自定义 JS 音源链路。

DLL 请求不经过本地官方签名器。私有服务配置和凭据不进入公共源码；模块返回的临时代理音频通过本机不透明票据转发，网页不接收私有代理地址。转发保留 Range、HEAD 与流式读取，不能把任意客户端地址当作可信模块地址。

## 检测与升级

共享模块检测固定呈现网易云、QQ、酷狗、酷我、汽水、JOOX 六个平台。旧 DLL 缺少检测结果时显示需要重新导入新版模块，不伪造成功或延迟。某个平台的上游拒绝请求时显示失败，这与“界面没显示该平台”不同。

替换便携版不自动更换用户已导入的 DLL。用户需要在设置中手动导入更新后的模块。开发用原始 DLL 和已有保护壳构建均属于敏感文件，不应提交公共仓库；保护壳不构成无法提取凭据的保证。
